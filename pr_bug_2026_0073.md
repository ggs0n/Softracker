## Summary
- add a one-submit client-side lock to the Stripe checkout form on the payment page
- disable the checkout button immediately after the first submit and change the label to "Redirecting to Stripe..."
- prevent rapid repeated clicks or Enter key resubmits from starting multiple checkout attempts before redirect
- add a regression test that locks in the single-submit guard markup and script

## Validation
- `dotnet build WFHMonitor/WFHMonitor.csproj -v minimal`
- `dotnet test WFHMonitor.Tests/WFHMonitor.Tests.csproj -v minimal`

## Notes
- this is the smallest safe fix for duplicate checkout submission without introducing server-side payment session persistence or a new payment table
